RIWIMEDICARE - GUIA DE CONSULTAS POSTMAN
Actualizada hasta Fase 12: Swagger incluido.

URL BASE
http://localhost:3000

DOCUMENTACION SWAGGER
http://localhost:3000/api-docs
En Swagger usa Authorize y pega el JWT para probar rutas protegidas.

IMPORTANTE
1. Para solicitudes con JSON: Body > raw > JSON.
2. No envies datos por Params cuando esta guia indique Body.
3. Las rutas de clinicas exigen un token JWT de un usuario ADMINISTRADOR.
4. Para agregar el token en Postman: Authorization > Auth Type: Bearer Token > pega solo el valor de token.

============================================================
1. VERIFICAR LA API
============================================================
Metodo: GET
URL: http://localhost:3000/health
No requiere token.

Respuesta esperada: 200 OK.

============================================================
2. REGISTRAR USUARIO
============================================================
Metodo: POST
URL: http://localhost:3000/auth/register
No requiere token.

Body:
{
  "nombre": "Administrador Principal",
  "email": "administrador@riwimedicare.com",
  "password": "ClaveSegura123",
  "rol": "ADMINISTRADOR"
}

Roles validos:
- ADMINISTRADOR
- GESTOR_SOLICITUDES

Respuesta esperada: 201 Created.
La respuesta incluye un token JWT. El correo debe ser unico.

25. CREAR OTRO INVENTARIO EN EL MISMO ALMACEN
============================================================

  "codigo": "MED-IBU-400",
  "descripcion": "Antiinflamatorio no esteroideo",
  "presentacion": "Caja por 50 tabletas",
  "unidad_medida": "TABLETA"
}

Luego usa el id del nuevo medicamento para crear su inventario.
Si el nuevo medicamento tiene id 2:
Metodo: POST
URL: http://localhost:3000/inventarios
Requiere token de ADMINISTRADOR.

Body:
{
  "almacen_id": 1,
  "medicamento_id": 2,
  "cantidad_disponible": 80,
  "stock_minimo": 15
}

Respuesta esperada: 201 Created.
Tambien puedes crear otro almacen y combinar su id con medicamento_id: 1.

============================================================
26. CREAR SOLICITUD DE ABASTECIMIENTO
============================================================
Metodo: POST
URL: http://localhost:3000/solicitudes
Requiere token de ADMINISTRADOR o GESTOR_SOLICITUDES.

Body:
{
  "clinica_id": 1,
  "almacen_asignado_id": 1,
  "observaciones": "Solicitud de abastecimiento mensual",
  "detalles": [
    {
      "medicamento_id": 1,
      "cantidad_solicitada": 20,
      "observaciones": "Entrega prioritaria"
    }
  ]
}

El usuario solicitante se obtiene del token, por eso no envies usuario_solicitante_id.
La clinica, el almacen y los medicamentos deben existir y estar activos.
Cada cantidad_solicitada debe ser un entero mayor que cero.
El inventario del almacen debe tener cantidad disponible suficiente para cada medicamento.
Una solicitud puede incluir varios objetos dentro de detalles.
Respuesta esperada: 201 Created.

============================================================
28. CAMBIAR ESTADO DE UNA SOLICITUD
============================================================
Metodo: PATCH
URL: http://localhost:3000/solicitudes/1/estado
Requiere token de ADMINISTRADOR o GESTOR_SOLICITUDES.

Body de ejemplo para aprobar:
{
  "estado": "APROBADA",
  "observacion": "Solicitud aprobada"
}

Estados y transiciones permitidas:
PENDIENTE -> APROBADA, RECHAZADA o CANCELADA.
APROBADA -> CANCELADA.
ASIGNADA -> DESPACHADA o CANCELADA.
DESPACHADA -> COMPLETADA.
RECHAZADA, COMPLETADA y CANCELADA son estados finales.

No envies ASIGNADA por esta ruta. Usa la consulta 29.
Cada cambio correcto crea un registro en historial_solicitudes.
Respuesta esperada: 200 OK.

============================================================
29. ASIGNAR ALMACEN A UNA SOLICITUD
============================================================
La solicitud debe estar en estado APROBADA.

Metodo: PATCH
URL: http://localhost:3000/solicitudes/1/asignar
Requiere token de ADMINISTRADOR o GESTOR_SOLICITUDES.

Body:
{
  "almacen_asignado_id": 1,
  "observacion": "Asignada al almacen central"
}

El almacen debe existir, estar activo y tener inventario suficiente para todos los detalles.
Esta operacion guarda usuario_asignador_id y fecha_asignacion.
Tambien cambia el estado de APROBADA a ASIGNADA y crea el historial.
Respuesta esperada: 200 OK.

33. CARGAR DATOS DESDE ARCHIVO JSON
============================================================
Metodo: POST
URL: http://localhost:3000/seed/json
Requiere token de ADMINISTRADOR.

En Body selecciona form-data.
Agrega una fila con Key: archivo.
En la columna de tipo, cambia Text por File.
Selecciona un archivo con extension .json de maximo 2 MB.
No uses raw ni Params para esta consulta.

El JSON puede incluir estos arreglos: usuarios, clinicas, almacenes,
medicamentos, inventarios, solicitudes, detalles, historial.
Todos los arreglos son opcionales, pero deben contener objetos validos.
Los arreglos se procesan en este orden: usuarios, clinicas, almacenes,
medicamentos, inventarios, solicitudes, detalles, historial.

Para inventarios, solicitudes, detalles e historial usa ids que ya existan
en la base al momento de la carga. Si en el mismo archivo creas entidades
nuevas, primero revisa sus ids en DBeaver y cargalas relacionadas despues.

Ejemplo basico de archivo JSON:
{
  "usuarios": [
    {
      "nombre": "Administrador Seeder",
      "email": "admin.seeder@riwimedicare.com",
      "password": "ClaveSegura123",
      "rol": "ADMINISTRADOR"
    }
  ],
  "clinicas": [
    {
      "nombre": "Clinica Seeder",
      "nit": "900555555-1",
      "direccion": "Calle 50 # 10-20"
    }
  ],
  "almacenes": [
    {
      "nombre": "Almacen Seeder",
      "direccion": "Carrera 25 # 40-15"
    }
  ],
  "medicamentos": [
    {
      "nombre": "Amoxicilina 500 mg",
      "codigo": "MED-AMOX-500",
      "unidad_medida": "CAPSULA"
    }
  ]
}

Respuesta esperada: 201 Created.
Si un dato falla, toda la carga se revierte y no se guardan datos parciales.

============================================================
ERRORES FRECUENTES
============================================================
401 Token de autenticacion requerido:
Falta configurar Authorization > Bearer Token en Postman.

401 Token de autenticacion invalido o vencido:
Haz login otra vez y copia un token nuevo.

403 No tienes permisos:
El token pertenece a GESTOR_SOLICITUDES. Para clinicas usa ADMINISTRADOR.

404 Cannot POST /ruta:
Revisa que el metodo y URL sean exactamente los indicados.

409 Conflicto:
El email, NIT o asociacion ya existe.
